# 수집 앱 (2단계)

선배님 삼성폰에서 카톡 알림을 읽어 메시지로 바꾸고, Apps Script 서버(`apps-script/`)로 보낸다.

## 동작 흐름

1. **알림 수신** `capture/KakaoListenerService`: 카톡 알림이 오면 제목, 본문, MessagingStyle 메시지 등을 꺼낸다.
2. **해석** `parse/KakaoParser`: 송신자, 채팅방, 메시지, 시각으로 바꾸고 메시지마다 ID를 만든다.
   카톡은 이전 메시지까지 담아 알림을 다시 올리므로, (방, 송신자, 시각, 내용)이 같으면 같은 ID가 된다.
3. **보관** `data/MessageStore`: 처음 보는 ID만 폰 DB에 넣는다. 서버가 처리 완료라고 답할 때까지 지우지 않는다.
4. **전송** `sync/Uploader`, `sync/Workers`: 새 메시지가 오면 3분 뒤 전송을 예약해 묶어서 보낸다. 인터넷이 없으면 연결될 때까지 기다리고, 실패하면 5분부터 점점 간격을 늘려 다시 시도한다.
5. **생존 신호** `HeartbeatWorker`: 한 시간마다 서버에 신호를 보낸다. 남은 메시지가 있으면 전송도 다시 예약한다.

## 메시지를 놓치지 않기 위한 처리

| 상황 | 처리 |
| --- | --- |
| 인터넷 끊김, 서버 오류 | 폰 DB에 남겨 두고 다시 시도 |
| Gemini 판단 실패 | 서버가 `retry`로 돌려주면 남겨 두고 나중에 다시 보냄 |
| 같은 메시지가 알림에 반복 | 메시지 ID로 걸러 한 번만 보냄 (7일간 기억) |
| 토큰 오류 | 자동 재시도를 멈추고 화면에 오류 표시. 설정을 고친 뒤 "지금 보내기" |
| 시스템이 알림 수신을 끊음 | 다시 연결을 요청 (`requestRebind`) |

## 화면

설치할 때와 문제가 생겼을 때만 연다.

- **상태**: 알림 접근 권한, 배터리 최적화 제외, 보관 중인 메시지 수, 마지막 수집·전송·생존 신호, 최근 오류
- **권한**: 알림 접근 권한 설정, 배터리 최적화 제외 요청, 앱 정보(제한된 설정 허용, 배터리 "제한 없음")
- **서버 연결**: 웹 앱 URL과 API 토큰 입력, 저장하고 연결 테스트
- **전송**: 보관 중인 메시지 지금 보내기

## 빌드와 테스트

JDK 17 이상과 Android SDK(platform 35)가 필요하다. 최소 지원 버전은 Android 9(API 28)다.

```bash
cd android-app
./gradlew testReleaseUnitTest   # 알림 해석, 전송 로직 단위 테스트
./gradlew lintRelease
./gradlew assembleRelease       # app/build/outputs/apk/release/app-release.apk
```

## 남은 일

- **0단계 결과 반영**: `KakaoParser`의 규칙은 안드로이드 MessagingStyle 규격을 기준으로 한 가정이다. 진단 기록이 오면 실제 기록(내용은 가림)을 `KakaoParserTest`에 넣고 규칙을 맞춘다. `DiagFixtures.fromDiagLine`이 진단 기록 한 줄을 그대로 테스트 입력으로 바꿔 준다.
- **실기기 검증**: 아직 실제 기기에서 실행하지 않았다.
- **서명 키**: 지금은 디버그 키로 서명한다. 실사용(4단계) 전에 고정 키로 바꿔야 업데이트할 때 앱을 지우지 않아도 된다. 키는 저장소에 넣지 않는다.
