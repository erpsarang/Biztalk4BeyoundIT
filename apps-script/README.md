# Apps Script 서버 (1단계)

수집 앱이 보낸 카톡 메시지를 받아 Gemini로 판단하고 구글 시트에 기록한다. 앱의 생존 신호가 끊기면 이메일로 경고한다.

| 파일 | 내용 |
| --- | --- |
| `src/Code.js` | 서버 코드 전체. 편집기에서는 `Code.gs` 한 파일로 붙여 넣는다 |
| `src/appsscript.json` | 매니페스트. 시간대(서울), 필요한 권한, 웹 앱 설정 |
| `test/` | Node로 돌리는 테스트. 시트·Gemini·메일을 흉내 내서 검증한다 |

## 시트 구성

`setup()`을 실행하면 아래 탭이 만들어진다.

| 탭 | 내용 |
| --- | --- |
| 메시지 | 일자, 송신자, 채팅방, 메시지, 카테고리, 수집 사유, 처리 상태(드롭다운) |
| 지정인 | 이름, 메모. A열 이름이 카톡 표시 이름과 같으면(공백·대소문자 무시) 무조건 저장한다 |
| 상태 | 마지막 생존 신호, 마지막 메시지 수신, 앱 버전, 기기, 마지막 오류, 경고 메일 발송 시각 |
| _처리기록 | 숨김 탭. 중복 저장을 막기 위한 메시지 ID 기록. 14일 지나면 자동 삭제 |

## 설치 순서

테스트는 본인 구글 계정으로 먼저 하고, 실사용할 때 선배님 구글 계정에 같은 순서로 다시 설치한다.

1. **Gemini API 키 발급**: https://aistudio.google.com/apikey 에서 "API 키 만들기". 무료 요금제로 충분하다.
2. **시트 만들기**: 구글 시트에서 빈 스프레드시트를 만들고 이름을 정한다. 예: "카톡 비즈니스 메시지"
3. **스크립트 붙여 넣기**
   1. 시트 메뉴 **확장 프로그램 → Apps Script**
   2. 왼쪽 ⚙️ **프로젝트 설정** → "편집기에서 'appsscript.json' 매니페스트 파일 표시" 체크
   3. 편집기로 돌아와 `appsscript.json` 내용을 `src/appsscript.json`으로 바꾼다
   4. `Code.gs` 내용을 모두 지우고 `src/Code.js` 내용을 붙여 넣은 뒤 저장(Ctrl+S)
4. **스크립트 속성 추가**: ⚙️ 프로젝트 설정 → 스크립트 속성 → 속성 추가

   | 속성 | 값 | 필수 |
   | --- | --- | --- |
   | `GEMINI_API_KEY` | 1번에서 받은 키 | 예 |
   | `ALERT_EMAILS` | 경고 받을 메일, 쉼표로 구분 (본인, 선배님) | 예 |
   | `GEMINI_MODEL` | 기본값 `gemini-2.5-flash`. 모델이 바뀌면 여기서 변경 | 아니오 |
   | `ALERT_HOURS` | 신호가 몇 시간 없으면 경고할지. 기본값 `3` | 아니오 |

5. **`setup` 실행**: 편집기 위쪽 함수 목록에서 `setup` 선택 → ▶ 실행
   - 권한 요청이 나오면 계정 선택 → "고급" → "(프로젝트 이름)(으)로 이동(안전하지 않음)" → 허용. 본인이 만든 스크립트라 구글 검증을 받지 않아서 나오는 경고다.
   - 실행 로그에 나오는 **API_TOKEN**을 복사해 둔다. 앱 설정에 입력할 값이다.
6. **`testGemini` 실행**: 샘플 메시지 3개의 판단 결과가 로그에 나오면 키와 모델이 정상이다. 시트에는 쓰지 않는다.
7. **웹 앱 배포**: 오른쪽 위 **배포 → 새 배포** → 유형 ⚙️ **웹 앱**
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - 배포 후 나오는 **웹 앱 URL**을 복사해 둔다. 앱 설정에 입력할 값이다.
   - 접근은 API_TOKEN으로 막는다. URL과 토큰은 다른 사람에게 알려 주지 않는다.
8. **동작 확인** (PC 명령 프롬프트 또는 터미널):

   ```bash
   curl -L -H "Content-Type: application/json" -d "{\"token\":\"API_TOKEN\",\"type\":\"heartbeat\",\"appVersion\":\"curl\"}" "웹 앱 URL"
   ```

   `{"ok":true,...}`가 나오고 시트 상태 탭의 "마지막 생존 신호"가 바뀌면 성공이다.

코드를 고친 뒤에는 **배포 → 배포 관리 → ✏️ 편집 → 버전: 새 버전 → 배포**로 올린다. 이렇게 하면 웹 앱 URL이 바뀌지 않는다.

## 앱 연동 규격

`POST` 웹 앱 URL, 본문은 JSON. Apps Script 웹 앱은 302 리디렉션 뒤에 결과를 주므로 클라이언트는 리디렉션을 따라가야 한다. HTTP 상태는 항상 200이므로 성공 여부는 `ok`로 판단한다.

```json
{
  "token": "API_TOKEN",
  "type": "messages",
  "appVersion": "1.0",
  "device": "SM-S921N",
  "messages": [
    {
      "id": "중복 제거 키 (같은 메시지는 항상 같은 값, 200자 이하)",
      "receivedAt": 1761955200000,
      "sender": "카톡 표시 이름",
      "room": "단톡방 이름, 1:1이면 빈 문자열",
      "isGroup": false,
      "text": "메시지 원문"
    }
  ]
}
```

- `type`이 `heartbeat`이면 `messages` 없이 생존 신호만 기록한다.
- 한 번에 최대 50건.

응답:

```json
{ "ok": true, "done": ["id", "..."], "retry": ["id"], "stored": 1, "aiError": "선택: AI 실패 사유" }
```

| 필드 | 앱이 할 일 |
| --- | --- |
| `done` | 폰 DB에서 지운다. 저장됨, 관련 없음, 이미 처리됨, 형식 오류를 모두 포함한다 |
| `retry` | 폰 DB에 남겨 두고 나중에 다시 보낸다. AI 판단이 실패한 메시지다 |
| `ok: false` | 전부 남겨 두고 다시 보낸다. `error`가 `unauthorized`면 토큰 설정을 확인하도록 사용자에게 알린다 |

## 처리 규칙

- 지정인이 보낸 메시지는 항상 저장한다. AI가 실패해도 카테고리를 "미분류"로 저장한다.
- 그 외 메시지는 Gemini가 관련 있다고 판단한 것만 저장한다. 애매하면 저장하도록 프롬프트를 썼다.
- 카테고리는 기존에 쓰인 이름을 우선 재사용한다. 공백만 다른 이름("고객 요청"과 "고객요청")은 기존 이름으로 맞춘다.
- `=`, `+`, `-`, `@`로 시작하는 값은 수식으로 실행되지 않도록 앞에 `'`를 붙인다.
- 생존 감시는 30분마다 실행된다. 신호가 `ALERT_HOURS`시간 넘게 없으면 경고 메일을 한 번 보내고, 신호가 돌아오면 복구 메일을 보낸다.
